# ReShade-HDR-Simulate-Oversaturation

[English](README.md) | [简体中文](README.zh-CN.md)

一个 ReShade shader,用来复现经典的"窄色域内容在没做色彩管理的情况下被宽色域屏幕直接显示"效果——也就是很多人记忆里 SDR 时代那种没做好色彩管理时特有的、浓郁过饱和的色彩观感。

和通用的饱和度/自然饱和度 shader 不一样,这个不是靠 HSV/HSL 数学去拉饱和度,而是复现了这个效果背后真实的物理机制:把你 HDR 管线里正确显示的颜色,转换回 Rec.709/sRGB 参考下的线性光,再用**错误的**(更宽的)原色——Display P3 而不是 sRGB——重新混色,这正是显示器收到 sRGB 信号、却没做转换直接当成自己原生宽色域 RGB 去解读时发生的事情。

因为这是真实的原色矩阵变换,红绿蓝三个通道是联动缩放的,所以像黄色这种颜色会变得更浓郁,而不会像普通的单通道饱和度拉伸那样在高饱和区域出现色相跑偏。这也是一个固定的线性变换,对任意亮度(包括远超 SDR 参考白的 HDR 高光)都一视同仁地处理,所以不存在裁切、不需要一个容易填错的参考白参数,也不会有高光细节丢失的问题。

只在 ReShade 后台缓冲区处于 HDR 色彩空间(scRGB 或 HDR10 PQ)时生效;SDR 下不做任何处理。

## 原理

1. 把当前像素从 HDR 后台缓冲区(scRGB 线性或 HDR10 PQ)解码到 XYZ。
2. 把这个 XYZ 转换成 Rec.709/sRGB 参考下的线性光。
3. 用 Display P3 的原色而不是 sRGB 去重新混色这份线性光——这就是那个"bug"。
4. 转换回你显示器实际需要的输出格式,正确上屏。

## 参数说明

| 参数 | 说明 |
|---|---|
| **色彩空间判断方式(Color Space Mode)** | `自动` 默认用 ReShade 编译时检测到的色彩空间。如果游戏内切换 HDR 开关后效果不再响应,大概率是 ReShade 没能正确刷新色彩空间检测——手动切换成 `强制 HDR10 PQ` 或 `强制 scRGB` 即可修正(不需要重启,和其他滑条一样实时生效)。`强制关闭` 则完全禁用效果。 |
| **效果强度(Effect Strength %)** | 0 = 正常/正确颜色,100 = 完全体验效果,可在中间取值做混合强度调节。 |

## 安装

1. 把 `SimulateSRGBAsP3.fx` 放进你的 ReShade shaders 文件夹(和你其他 `.fx` 文件同一个位置)。
2. 在游戏内和 Windows 里都打开 HDR。
3. 在 ReShade 悬浮菜单里勾选 `SimulateSRGBAsP3`。

如果你还在用别的饱和度/调色类 shader,把这个放在效果列表里它们**上面**(ReShade 是从上到下依次处理),让它先处理颜色,再叠加其他调整。

## 局限

- 假设游戏内容本身是按 Rec.709/sRGB 色域制作的,覆盖了绝大多数游戏。原生宽色域渲染的游戏不会被正确处理。
- `色彩空间判断方式` 的自动检测依赖 ReShade 在编译时正确汇报 `BUFFER_COLOR_SPACE`。已知在同一局游戏里反复切换 HDR 开关后,这个值有时会刷新不及时——遇到这种情况用手动覆盖选项即可。
